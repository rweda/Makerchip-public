Class: IdePlugin

Defined in: ../doc/cleaned_coffee_plugin/IdePlugin.coffee

Overview

Base class for third-party platform integration with the Makerchip IDE.

Extend this class to customize IDE behavior and interact with the IDE and its compilations.

See the README.md (under "Extras") for an overview.

# (Promise<String>) openThirdPartyPane(mnemonic, contentType, contentParams, options)

Public API method to open a third-party-provided pane with external content. This enables platforms to inject custom panes into the IDE. Panes are provided by the embedding platform (e.g., VS Code extension, web app).

Currently supports:

  • "pdf" - Display a PDF document via URL. The viewer's own origin check is disabled, but the sandbox CSP still governs the fetch (connect-src 'self' https: blob:), so https:, blob: and same-origin URLs work. file:// does NOT: browsers block local-file loads from an http(s) document beneath CSP, so no CSP change can enable it (see doc-src/plugin/Third_Party_Pane_API.md). Pass a blob: URL to present local bytes.
  • "iframe" - Embed external web content via URL

All third-party panes are closable by default.

The mnemonic is automatically uniquified if there's a collision with existing panes (based on sanitized HTML ID). Uniquification appends +# or -#

Third-party panes are always included in layout state. Recoverable panes (default) include full creation data and can be automatically recreated. Non-recoverable panes are tracked with null (position visible, but can't be recreated if not present).

Recoverable panes retain the contentParams and can provide it in layout state (see `getLayoutState()`)
to enable automatic recreation in another IDE instance.

Examples:

# Open a PDF document
ide.api.openThirdPartyPane("My Guide", "pdf", {
  contentUrl: "https://example.com/guide.pdf"
})

# Open external documentation in iframe
ide.api.openThirdPartyPane("External Docs", "iframe", {
  contentUrl: "https://docs.example.com"
}, {
  background: true  # Don't activate immediately
})

Parameters:

  • mnemonic ( String ) — Requested identifier for the pane (used as tab title, auto-uniquified if needed)
  • contentType ( String ) — Type of content: "pdf" or "iframe"
  • contentParams ( Object ) — Content-specific parameters: @option contentParams {String} contentUrl URL for the content (required, supports any origin)
  • options ( Object ) — Control options (optional): @option options {Boolean} background If true, don't activate pane after opening (default: false) @option options {Boolean} nonTransferrable If true, mark as non-transferrable to optimize memory (default: false)

Returns:

  • ( Promise<String> ) — Promise that resolves to actual mnemonic used (may differ from requested if uniquified), or null on error

# (Promise) busEmit(type, payload, target, agent)

Public API method to emit an application event onto the IDE bus as a platform participant. Panes (and the IDE) receive it through their subscriptions, filtered by type and source; the source is always within the reserved platform namespace, so it cannot be spoofed as "ide" or a pane. This is a fire-and-forget broadcast onto the same ext/<type> channel panes use — an existing pane whose contract names "platform" in a subscription's sources receives it with no change. TRUST: the platform namespace is only mostly trusted — anyone can host a Makerchip Plugin, and the host may relay this API to AI agents — so recipients opt in per source. Omit agent for the host's own actions (source "platform"); pass an agent tag (e.g. "ai") to mark an emit the host relays on a less-trusted agent's behalf (source "platform.ai"). Recipients can then accept "platform" only or a specific "platform." via exact sources; to accept the whole family it omits sources and tests source.startsWith("platform"). The platform can never reach reserved first-party ide/ events.

Examples:

await ide.api.busEmit("sourceAsm", { source, asm })              # as "platform"
await ide.api.busEmit("sourceAsm", { source, asm }, null, "ai")  # as "platform.ai"

Parameters:

  • type ( String ) — Event type (e.g. "sourceAsm").
  • payload ( * ) — Structured-clone-safe payload.
  • [target] ( String|Array<String> ) — Optional recipient identity whitelist.
  • [agent] ( String ) — Optional agent tag; omit for source "platform", or pass e.g. "ai" for source "platform.ai". Only ever extends the "platform" namespace.

Returns:

  • ( Promise ) — Resolves once the emit has been dispatched.

# (Promise) callPane(mnemonic, method, args, timeoutMs)

Public API method to call a method on a connected third-party pane and await its result (host->pane RPC). Names a pane the caller opened (by its reserved/uniquified mnemonic) and forwards method/args over that pane's channel; the pane must have declared rpc: true and implemented a handler for method. This is the request/response complement to {busEmit}'s fire-and-forget broadcast: use it when you need a value back (e.g. tell a pane to run and wait for its outcome). The IDE is a pass-through — it interprets neither the method nor the arguments.

Examples:

result = await ide.api.callPane("Compiler Explorer+2", "runOnWarpV", [])

Parameters:

  • mnemonic ( String ) — The target pane's mnemonic (as returned by reservePane/openThirdPartyPane).
  • method ( String ) — The pane method to invoke.
  • [args] ( Array ) — Positional arguments (structured-clone-safe).
  • [timeoutMs] ( Number ) — Optional response timeout in ms (default 30000).

Returns:

  • ( Promise ) — Resolves with the pane's result; rejects on pane error, timeout, or if the pane is unknown or did not opt into RPC.

# (Promise<Object>) getLayoutState(options = {})

Public API method to get the current layout state of the IDE. The state includes the arrangement of panes, splits, and active tabs. It may include recovery data for reconstructing third-party panes. This can be used to save and restore user's layout preferences, transfer to a different IDE instance, or to inspect (then modify) the layout.

The returned state is a recursive tree representing the split layout hierarchy. Each node is either a FlexSplit (has 'sides' property with left/right or top/bottom children) or a TabbedView (has 'panes' array). Split direction is inferred from which children exist (left+right = horizontal, top+bottom = vertical).

TabbedView panes array contains mnemonic strings, or, for transferrable third-party panes with forTransfer: true, objects containing: {mnemonic, contentType, contentParams}

See Plugin_API.md (in Extras) for complete layout state and third-party pane documentation.

Examples:

Get and save layout state for future recovery 

const state = await ide.getLayoutState({forTransfer: true});
localStorage.setItem('layout', JSON.stringify(state));

Restore saved layout 

const saved = JSON.parse(localStorage.getItem('layout'));
await ide.setLayoutState(saved);

Get state for same-instance rearrangement 

const state = await ide.getLayoutState();  // forTransfer not needed

Example state structure (forTransfer: true) 

{
  sides: {
    left: {
      panes: ["Editor", "Nav-TLV"],
      activePane: "Editor"
    },
    right: {
      sides: {
        top: {
          panes: [
            "Diagram",
            {
              mnemonic: "User Guide",
              contentType: "pdf",
              contentParams: {contentUrl: "https://example.com/guide.pdf"}
            }
          ],
          activePane: "Diagram"
        },
        bottom: {
          panes: ["Waveform", "Log"],
          activePane: "Waveform"
        }
      },
      splitAt: 0.6
    }
  },
  splitAt: 0.3
}

Parameters:

  • options ( Object ) — Optional configuration

Options Hash: (options):

  • forTransfer ( Boolean ) — If true, include third-party panes for cross-instance transfer (default: false). Set to true when saving state that may be restored in a different IDE instance that may not have the panes. Set to false (default) when rearranging within the same instance where panes already exist.

Returns:

  • ( Promise<Object> ) — Promise resolving to the serializable layout state object

# (Promise<Blob|null>) captureVideo(startCyc, endCyc, options)

Capture the VIZ simulation as a video (APNG, GIF, MP4, or WebM) and resolve to a Blob, optionally downloading it. Rendering is performed headlessly (via the VIZ pane's VizRecorder + FFmpeg) blocking in the foreground process. The output format is chosen from the format option if given, else the filename extension (.apng, .gif, .mp4, .webm), else a frames-based default (GIF for a single-frame capture, MP4 for animated captures). Because format is independent of filename, a caller can request a format while returning the blob only (no download). Throws an error if the simulation data is not available or has no simulation data.

Video capture steps through cycles like VIZ playback, with flexible camera control via keyframes. Each keyframe specifies:

  • cycle: may be fractional; monotonically increasing from earlier keyframes, spanning at least startCyc..endCyc across all keyframe cycles.
  • scale and focus: the zoom and center point of the view.
  • width/height: the reference view within which scale/focus are interpreted. The keyframe view is fit within the recording dimensions, so framing stays consistent at any recording size (when width/height are provided).

Keyframes are interpreted according to the mode option:

  • 'viz-relative' (default): scale is a multiplier on the current VIZ scale (0.5 = zoom out 2x, 2.0 = zoom in 2x) and focus is an offset as a fraction of the current view's visible width/height. keyframes may be omitted to record the current view (a single default keyframe).
  • 'fit-relative': like viz-relative, but the base is the whole-design contain-fit AT THE RECORDING SIZE rather than the current pane view (scale 1 = whole design framed, 2 = 2x zoom in; focus is a fraction of the fit's visible area). This is the reliable way to frame a recording without hand-tuning scale, since it is independent of the pane's aspect and scroll position. keyframes may be omitted to record the whole-design fit. Equivalent to using IdePlugin#fitKeyframe as the base keyframe.
  • 'absolute': scale/focus are absolute VIZ coordinates, with the reference view given by each keyframe's width/height (or default.width/height). The current view is NOT used, so keyframes is REQUIRED (at least one entry); default only supplies values for properties an individual keyframe omits and does not substitute for the array.

Frame capture behavior

  • startCyc >= 0: captures only the final (settled) frame of the start cycle.
  • subsequent cycles (startCyc+1..endCyc): captures a frame every delta = 1000/fps ms through the cycle duration.
  • startCyc = -1: skips cycle -1, enabling capture of cycle 0's animation frames.

Examples (fps=3, cyclesPerSecond=1, delta=333ms): captureVideo(0, 0, {fps: 3}) → 1 frame at 1000ms (final state of cycle 0) captureVideo(0, 1, {fps: 3}) → 4 frames: 1000ms (cyc 0 final), 333/666/1000ms (cyc 1) captureVideo(-1, 0, {fps: 3}) → 3 frames at 333/666/1000ms (cycle 0 animation only)

Limitations

  • Maximum 2000 frames per capture (~67s @ 30fps, ~33s @ 60fps).
  • All frames are held in memory during encoding (no streaming).

  • For longer captures, reduce fps/cyclesPerSecond or use screen-recording software.

# (Promise<Object|null>) getKeyframe()

Capture the current VIZ state as an absolute keyframe object.

Returns a keyframe describing the current cycle, camera positioning (scale and focus), and canvas bounds. The keyframe is in absolute form, suitable for use in captureVideo's keyframes array (with mode: 'absolute'). The included width/height record the canvas dimensions this keyframe was captured at, ensuring the keyframe resolves consistently even if the recording is at a different size.

Keyframes are typically captured at different simulation cycles or camera positions (via manual zoom/pan in the VIZ) and then used to animate the camera during video capture. The captureVideo method interpolates between keyframes using Catmull-Rom splines for smooth motion.

Common workflow:

  1. Navigate to a cycle and camera position in the VIZ
  2. Call getKeyframe() to capture the state
  3. Repeat for other positions

  4. Pass collected keyframes to captureVideo with mode: 'absolute'

                            or null if VIZ is not available

Examples:

Capture two keyframes and animate between them 

// Navigate to start position in VIZ
await ide.api.setCycle(0);
const kf1 = await ide.api.getKeyframe();

// Navigate to end position
await ide.api.setCycle(100);
// ... manually zoom/pan in VIZ to desired end view ...
const kf2 = await ide.api.getKeyframe();

// Capture video with animated camera
await ide.api.captureVideo(kf1.cycle, kf2.cycle, {
  mode: 'absolute',

# (Promise<Object|null>) fitKeyframe(width, height)

Compute an absolute contain-fit keyframe that frames the whole design for a target recording size (fits the design's bounding box to width x height, centered), WITHOUT changing the current view.

Rarely needed. For a whole-design capture, or a zoom into it, prefer captureVideo's mode: 'fit-relative', which frames the fit automatically with no keyframe. Reach for fitKeyframe only when you need the fit as an absolute keyframe: to interpolate a whole-design frame together with IdePlugin#getKeyframe views in one mode: 'absolute' path, or when you want its concrete numeric scale/focus. The returned keyframe's width/height equal the requested size, so pass the same width/height to captureVideo.

                            or null if VIZ is not available

Examples:

Glide from the whole-design frame to a hand-positioned getKeyframe view (absolute) 

const fit = await ide.api.fitKeyframe(350, 250);
await ide.api.setCycle(100);                  // ...zoom/pan to a detail view...
const detail = await ide.api.getKeyframe();
await ide.api.captureVideo(fit.cycle, detail.cycle, {
  width: 350, height: 250,
  mode: 'absolute',
  keyframes: [fit, detail],
  filename: 'framed.mp4'
});

Parameters:

  • width ( Number ) — Target recording width in pixels
  • height ( Number ) — Target recording height in pixels

Returns:

  • ( Promise<Object|null> ) — Promise resolving to keyframe {cycle, scale, focus: {x, y}, width, height},

# (Promise<Array<Object>>) getAvailablePanes()

Public API method to get all available panes. Returns an array of pane metadata including main IDE panes and static panes. Useful for discovering what panes can be opened via openPane() or activatePane().

# (Promise<void>) updatePlayState(isPlaying, cycleTimeout, startCyc, endCyc)

Public API method to control waveform playback. This starts or stops automatic cycling through waveform time steps. Optionally set speed and/or starting and ending cycles for bounded playback (for isPlaying == true).

Examples:

// Start playing from current position
await ide.api.updatePlayState(true);

// Stop playing
await ide.api.updatePlayState(false);

// Play from cycle 10 to cycle 50 at 500ms per cycle
await ide.api.updatePlayState(true, 500, 10, 50);

// Play from cycle 0 to end of waveform
await ide.api.updatePlayState(true, undefined, 0);

Parameters:

  • isPlaying ( Boolean ) — true to start playback, false to stop (must be the only argument if false)
  • cycleTimeout ( Number ) — Optional delay in milliseconds between cycles (default: keeps current timeout, initially 1000ms)
  • startCyc ( Number ) — Optional starting cycle - if provided, jumps to this cycle before starting playback
  • endCyc ( Number ) — Optional ending cycle - if provided, playback stops at this cycle; otherwise plays to end of waveform

Returns:

  • ( Promise<void> ) — Promise that resolves when play state is updated

# (Promise<Boolean>) highlight(id, accumulate = false)

Public API method to highlight a logical entity across all IDE views. Logical entities are circuit elements identified by their TL-Verilog paths. Highlights appear in the Diagram, Waveform, and Nav-TLV panes.

Examples:

// Examples of highlighting entities of various types, clearing previous highlights
// Pipesignal:
await ide.api.highlight('/cpu|my_pipe$data')
// Scope (behavioral hierarchy level or pipeline):
await.ide.api.highlight('/cpu')
await.ide.api.highlight('/cpu|my_pipe')
await.ide.api.highlight('/cpu|my_pipe/reg')
// Pipeline stage (pipestage):
await.ide.api.highlight('|my_pipe@2')  // (without any hierarchy, just pipeline and stage)

// Add to existing highlights (Ctrl+click behavior)
await ide.api.highlight('|fetch@1', true);

Parameters:

  • id ( String ) — The unique identifier (logical entity path) to highlight
  • accumulate ( Boolean ) — Optional - if true, adds to existing highlights (Ctrl+click behavior); if false, replaces all highlights (default: false)

Returns:

  • ( Promise<Boolean> ) — Promise that resolves to true if entity was found in the DOM and highlight was applied, false if entity not found or ID invalid.
